# Posterize Time — пакет для интеграции (12 ноября 2026)

В рамках переделки группы Textures подготовлены и анимированы бумажные текстуры. Этот шейдер дополняет их постеризацией времени: движение пользовательского видео становится ступенчатым, как в стоп-моушене.

## Управление
Интенсивность 100% — 5 обновлений изображения в секунду.
75% — 11.25, 50% — 17.5, 25% — 23.75 кадров/с.
При положительной интенсивности частота = 30 − 25 × intensity (0…1).
Ровно 0% — полный обход удержания, исходная частота, включая видео 60 fps. Новые кадры не создаются: частота не может превысить доступные исходные кадры. Длительность и звук сохраняются.
Промежуточные значения меняют временную сетку, без смешивания кадров по прозрачности.
В билдере интенсивность слоя задаёт MAX/DEFAULT cadence; общая сила масштабирует её от MIN=0.

## Что передаём
- ISF_METAL/v1/PosterizeTime/PosterizeTime.ps и .vs — оба актуальных Metal-шейдера.
- PosterizeTime.json — конфигурация ISF.
- Posterize_Time_Prototype_mobile.zip — пример: all_in_one.json + Layers.zip.
- Исходники проверок Metal/JS и инструкция.

## Интеграция
1. Добавить/заменить оба .ps/.vs в глобальных ресурсах приложения ISF_METAL/v1/PosterizeTime/. Копии в resources пресета служат для передачи; штатный загрузчик читает глобальный ISF_METAL.
2. effectType=isf, shaderPath=v1/PosterizeTime/PosterizeTime. Единственный float input — cadence, DEFAULT=1, MIN=0, MAX=1; intensityParamNames=[cadence]. framesPerSecond из предыдущей версии удалён, оба шейдера и JSON нужно обновлять вместе.
3. Сохранить три PASSES, PERSISTENT и порядок. HoldClock должен иметь размер 2×1; выражения WIDTH/HEIGHT компенсируют коэффициент 0.77 host.
4. Кадры обрабатывать последовательно, историю хранить отдельно для каждого клипа/экземпляра. При seek, loop, trim/time-remap, смене исходника и пересоздании эффекта сбрасывать историю.
5. Для произвольного доступа нужен прогрев от начала текущего интервала либо квантованный запрос исходного кадра в движке. Один шейдер не может получить пропущенный исходный кадр.
6. При общей силе 0 эффект можно пропускать. Проверить сброс истории при возврате из bypass.

Проход 0 захватывает/удерживает кадр; проход 1 сохраняет byte-packed номер интервала и интенсивность в RGBA8/BGRA8; проход 2 выводит удерживаемый кадр. Используется TIME видео и сетка floor(max(TIME,0)*fps+0.0001).
Пакет предназначен для разработки и тестирования iOS/Metal. Полная интеграция на телефоне и Android здесь не проверены.

## Проверить в приложении
Интенсивность 0/25/50/75/100%, исходники 24/29.97/30/60 fps, preview и экспорт, неизменные длительность/звук, seek/loop, два клипа подряд и независимые истории, сочетание с анимированными бумажными текстурами.
