The tests extract the original kernels, compile them at runtime on Apple M4,
prepare settings independently in Objective-C++, and compare browser output.
They use actual RGBA8 filter boundaries and RGBA16Float linear intermediates.
Native compiler fast math is disabled. Browser floating-point and quantization
differences remain: Adjust <=4/255 at isolated synthetic pixels, mean <0.07/255;
LUT <=1/255; Bloom <=1/255. No per-preset visual tuning was applied.

Scope: same SDR Rec.709 pixel frame, current checked host implementation,
and user-confirmed delivered Bloom v3. This is not a capture of the phone's
complete running pipeline or a decoder/HDR/P3 calibration. Different source
frames or app-level cached packages can still prevent a visual comparison.
